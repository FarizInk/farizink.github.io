# Diary Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A logged-in "Diary" view on Home: one-line composer that creates a note, a compact infinite feed of notes filtered by locally stored tags, and a small edit modal (title, plain-text description, public switch, delete).

**Architecture:** Pure helpers in `src/lib/diary.ts` (tested with `node --test`), four Svelte components under `src/components/diary/`, Home gains a Profile/Dashboard/Diary switcher. All data goes through the existing `src/lib/notes.ts` functions and the existing tags store — no backend or store changes.

**Tech Stack:** Svelte 5 runes, TypeScript, Tailwind 4 + Fariz DS (`$lib/components/ds`), svelte-sonner, boneyard-js, Node 24 test runner.

**Spec:** `docs/superpowers/specs/2026-10-26-diary-design.md`

## Global Constraints

- Logged-in only; Home switcher shows only when `localStorage.authToken` exists (existing Home logic).
- Empty tag filter = all notes (no `includeTags`); create with `tags: []`.
- New entries: `isPublic: true`.
- Description stored as HTML paragraphs produced by `textToHtml`.
- localStorage keys: `diaryTagIds` (JSON string[] of tag UUIDs), `homeView` (`'profile' | 'dashboard' | 'diary'`); migrate legacy `homeShowDashboard`.
- Fariz DS only: tokens, flat surfaces (no borders/shadows), DS components; both themes; mobile-first, feed `max-w-[640px]` centered.
- Copy (English, matches the site): placeholder `What's going on?`, empty feed `No entries yet — write the first one above`, end of feed `That's everything`, rich-text hint `Formatting from Notes will be simplified`, delete confirm `Tap again to delete`, filter empty label `All notes`.
- Git is read-only in this repo (CLAUDE.md): never commit; the user commits.
- `npm run check` must stay at the 78-error baseline; lint must stay at 7 errors.

## Review Focus

1. Description written in Notes with rich HTML (lists, `<strong>`, entities like `&amp;`) opened in the Diary modal → readable plain text, not raw tags; saving does not double-escape. *Test in Task 1 (`htmlToText` rich + entity cases).*
2. Corrupted/legacy localStorage (`diaryTagIds` = `"abc"` or `{}`; `homeShowDashboard` = `"true"`) → falls back to `[]` / migrates to `'dashboard'`, never throws. *Test in Task 1.*
3. Fast double Enter on the composer → exactly one note created. *Guard in Task 3 (`sending` flag), checked in Task 5 browser step.*
4. Changing the tag filter while a page is loading → stale page results must not be appended to the new filter's list. *Guard in Task 4 (request token), checked in Task 5.*
5. Infinite scroll on a short feed (sentinel visible immediately) → keeps loading until the viewport is filled or the last page, without duplicate pages. *Guard in Task 4 (`loading` lock + page counter), checked in Task 5.*
